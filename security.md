# OFUSCA Website Security Policy

## Important reality
No public website can be made impossible to clone or attack. A strong protection plan reduces risk through secure hosting, private source control, access control, monitoring, backups, and legal/copyright controls.

## Built-in protections in this package
- Security headers in `_headers` and `netlify.toml`.
- Strict Content Security Policy.
- Clickjacking protection.
- MIME sniffing protection.
- Referrer and browser-permission limits.
- Honeypot fields on forms.
- Basic browser-side form protection in `assets/js/main.js`.
- Proprietary all-rights-reserved license.
- Security page and reporting file.
- Blocked common attack probe paths.

## Required hosting practices
1. Use a private GitHub repository. Do not make the source code public.
2. Enable two-factor authentication for GitHub, Netlify, Google, PayPal/Stripe, and email accounts.
3. Give admin access only to trusted officers.
4. Use Netlify Identity/SSO or team permissions for maintainers.
5. Turn on Netlify spam filtering and form notifications.
6. Export form submissions regularly and back them up securely.
7. Do not store payment card details on this site.
8. Use official PayPal, Stripe, Zelle, Interac, or bank links for payments.
9. Review submitted photos and member spotlights before publishing.
10. Keep private information out of public pages.

## If a clone or fake site appears
- Take screenshots.
- Save the URL and date.
- Report the impersonation to the hosting provider.
- File a DMCA/copyright takedown if applicable.
- Notify members through official channels.
